- **A link's teardown could wait on a callback that needed the lock it held (#2751).** Removing
  a connection waited for the link's callbacks while holding the transport vertex's control
  lock. A callback inside a control-plane operation needs that lock, so the removal never
  finished. That happens when the operation arrived on the removed link itself, or on another
  link while the removed link's callback waited its turn. The waits now run after the lock is
  released. A link removed from its own callback is no longer joined from its own thread: the
  thread ends once that callback returns, and the link's destructor, run at the graph's next
  `collect()`, joins it. Self-healing links do the same for their sockets
  (`self_heal_link_t::stop_worker` joins only the dial worker). New
  `transport_t::on_own_thread()` tells an owner when a link must not be destroyed on the
  current thread.
