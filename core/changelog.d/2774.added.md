- **A per-session READ budget under contention (#2774), off by default.** A build that sets
  `static constexpr std::uint8_t kReadBudget = N;` in its `config_override.hpp` answers a READ
  this node terminates with the existing `tr::flow::backpressure` reply when it is beyond the
  sending session's N-th in the current run and at least two sessions have READ in that run. A
  session alone in a run is never refused, and neither is a WRITE, a subscribe, an AWAIT, a REPLY,
  or a frame this node forwards. The application closes a run with the new
  `fwd_router_t::close_read_run()`, for example from its idle task every 100 ms; the library reads
  no clock, and the call is a no-op when the budget is off. A session is one slot of the TCP or WS
  listener or the ESP-IDF WS link (each slot keeps its own count), or a whole link otherwise. Off
  (the default, `kReadBudget = 0`), every member the budget adds is an empty
  `[[no_unique_address]]` type and the check is not compiled: no byte, no branch. On (x86_64,
  measured), a stream-server session slot grows 8 B (a 4-byte tally plus padding), every
  `transport_t` 8 B (a pointer), the router 8 B (a 4-byte census word plus padding), and a
  registered link's receive context 0 B (its tally fits existing padding): a connected WS peer
  draws 16 B more. New public names: `tr::net::read_tally_t`, `no_read_tally_t`,
  `session_read_tally_t`, `inbound_read_tally_t`, `read_census_t`, `kReadBudgetOn`, and the
  protected `transport_t::inbound_tally_`, which a custom multi-session link points at the
  delivering session's tally.
