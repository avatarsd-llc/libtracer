- **A reply that times out no longer counts toward closing the session (#2921).** The httpd
  WebSocket link closed a session after three consecutive failed sends (#835), and an in-call reply
  the socket did not take within the send bound counted as one, so three slow replies in a row
  closed a slow but live peer. Now a hard socket error closes the session at once, and a reply
  that times out with nothing written is a counted drop (`tx_send_failed`) that marks the session
  stalled. While it is stalled its replies are written without waiting: a reply the socket takes
  whole ends the stall, one it takes nothing of is dropped, and one it takes part of is finished
  within one send bound. A stopped peer therefore costs the httpd task one send bound, then
  nothing, and is closed by the application's liveness check (`sweep`), which counts a stalled
  session as owing bytes. The default send bound is unchanged (208 ms at four peers and a 5 s
  watchdog).
