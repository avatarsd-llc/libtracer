- **One budget for the whole httpd WebSocket link, and the application's tick ends a wait
  (#2958).** The ingress drain budget was split into per-session shares, with a link-wide
  ceiling of twice the budget. A share spent by one session parked the httpd task that every
  session shares, so other sessions waited for the core's idle pass too. Now every session's
  frames count toward one budget, and the drain waits only once all sessions together have
  read it: a single busy session waits where it did before, and several sessions together read
  at most one budget, not two, before a wait. A wait now also ends at the application's next
  `sweep` or `flush_held`, so a core whose idle task does not run holds the link for at most
  one application tick. No timer and no clock read were added.
